## Q. 용어/아키텍쳐에도 proxy, agent 추가(enterprise) 의 기능을 추가해서. (2026-08-27)

**A.**
Vault Agent와 Vault Proxy는 애플리케이션 옆에서 별도로 실행되는 클라이언트 데몬으로, 애플리케이션 코드를 수정하지 않고도 Vault 인증·시크릿 조회를 대신 처리해준다. 둘 다 **Vault Enterprise 라이선스 없이 모든 Vault 바이너리에 기본 포함**되어 있어 "Agent/Proxy = Enterprise 전용"은 아니다.

- **Agent**: Auto-Auth, 토큰/리스 캐싱, Templating(시크릿을 파일로 렌더링), Process Supervisor(시크릿을 환경변수로 주입해 자식 프로세스 실행) 지원. **API Proxy 기능은 지원 중단(Deprecated)**되었고 공식문서는 Vault Proxy 사용을 권장한다.
- **Proxy**: Auto-Auth, 토큰/리스 캐싱, API Proxy 지원. Templating·Process Supervisor는 없다. 대신 **정적 시크릿(KV) 캐싱**을 지원한다.
- **Enterprise가 걸리는 지점은 딱 하나**: Proxy의 정적 시크릿 캐싱은 캐시 무효화를 위해 auto-auth 토큰으로 KV **Event Notifications**를 구독해야 하는데, Event Notifications 자체가 공식문서에 "Appropriate Vault Enterprise license required"로 명시된 **Enterprise 전용 기능**이다. 따라서 정적 시크릿 캐싱만 사실상 Enterprise 환경에서만 동작하고, 나머지 Agent/Proxy 기능은 OSS에서도 그대로 쓸 수 있다.
